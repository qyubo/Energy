# C 板控制逻辑参考（不改现有工程）

## 1. 当前代码事实

只读检查 `Energy_New/Master_energy_new` 后确认：

- `User/CAN/energy_can.[ch]` 已有 1～5 号节点、`0x300 + node` 命令 ID 和五种灯效命令。
- `Core/Src/app_threadx.c` 现已运行 `Energy_Task()` 和 `Bluetooth_Task()`。
- USART1 是 `PA9 TX / PB7 RX`，现为 `115200 8N1`；USART6 是 `PG14 TX / PG9 RX`，仍为 `921600 8N1`。
- `User/Bluetooth/bluetooth.c` 已在 USART1 上实现协议；`User/Energy/energy.c` 已实现小符和大符测试状态机。
- HC-42D 手册默认 `9600 8N1`，实际模块若仍为默认值，必须先配置到 115200 才能与当前主板相通。

当前固件已固定使用 USART1，请将 HC-42D 接到 USART1 并设置为 `115200 8N1`；若改用其他串口，必须同步修改固件。不要把 HC-42D 接到 USART3（当前为遥控器风格的 100000、9 位偶校验、仅接收）。

## 2. 接线

断电接线：

| HC-42D | C 板 |
|---|---|
| VCC | 稳定 3.3V 或模块允许的 5V供电 |
| GND | GND（必须共地） |
| TXD | 所选 USART_RX |
| RXD | 所选 USART_TX |

TX/RX 交叉。模块串口逻辑是 3.3V TTL，不是 RS232 电平；禁止接 24V，也不要经过 RS232 收发器。

## 3. 任务拆分

以下是后续重构建议，不是当前固件已实现的任务划分。目前固件以单个 `EnergyThread_Entry` 循环调用小符和蓝牙任务：

1. 当前固件 `BluetoothRx` 使用 USART1 单字节中断收集 JSON 行；日后若吞吐需求提高，可改为 DMA + IDLE。
2. `ProtocolParser`：按 LF 取完整 ASCII JSON，限制 1024 字节，校验字段后投递命令队列。
3. `EnergyGame`：唯一写游戏状态的任务；处理手机命令、压力事件、看门狗、随机目标和闪烁定时。
4. `CanOutput`：根据权威状态生成 5 个 CAN 命令；发送失败重试并记录故障。

不要在 UART 中断里随机、发 CAN 或延时闪烁。

## 4. 状态转换

```text
IDLE --START(SMALL)--> RUNNING(target=随机未完成节点)
RUNNING --正确HIT--> 标记节点完成 --> 还有节点：换随机目标
                                      全部完成：FLASHING
RUNNING --MISS/错误压力节点--> 清mask、round++、重新随机目标
FLASHING --250ms--> 亮/灭切换，累计10次 --> COMPLETE并保持FINISH灯效
任意运行态 --STOP/6秒看门狗--> IDLE并向5块板发OFF
```

大符测试另用交替阶段：随机两靶（手机选择击中则继续，选择未击中则重开）→ 留下一靶（手机选择击中或未击中都继续）→ 补随机一靶，另外三块进度增加一格。到第4格时再击中两靶中的一块，所有流水灯到第5格且留下最后可击打靶面；最后靶面击中才开始全红+八环闪烁，未击中则重开。手机测试约定模拟击中 `target`，而 `otherTarget` 是同阶段另一块亮靶。测试流程不设置自动击打超时；压力传感器尚未接入。

随机选择要从“未完成节点集合”中抽取，不能用 `rand()%5` 后无限重抽。上电时可用 ADC 噪声、硬件 RNG 或定时器抖动播种；测试时允许固定种子以复现问题。

## 5. 灯效计算

不要把每块板的灯效散落在多个分支里。写一个纯函数：

```text
for node=1..5:
  IDLE                          => OFF
  RUNNING && node==target       => TARGET_ARROW
  RUNNING && mask包含node:
      SMALL                     => SMALL_HIT
      LARGE                     => PROGRESS(level)
  RUNNING 其他                  => OFF
  FLASHING                      => flashOn ? FINISH : OFF
  COMPLETE                      => FINISH
```

状态先原子更新，再统一调用该函数刷新五块板。

## 6. 手机按钮与压力传感器并存

手机 `HIT` 是测试输入；真实压力传感器也可能产生命中。二者必须进入同一个 `EnergyGame` 队列，事件携带采样时的 `target + rev`。最先被接受的事件会增加 `rev`，后到事件因版本过期被丢弃，避免一次撞击计算两次。

当前需求的大符、小符手动测试都不启用击打超时，只由手机选择击中或未击中来推进。未来切换为正式训练模式时，再在主板增加策略字段，不要靠小程序后台计时。

固件端最终应通过以下条件；大小符手机测试逻辑已编译并经过主机状态测试，但仍需实物验证，压力事件尚未完成：

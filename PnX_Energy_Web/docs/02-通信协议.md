# 手机—主板通信协议 v1

## 1. 分层

HC-42D 只是透明通道：手机写 BLE `FFE1`，模块把字节送到 UART；主板 UART 发回的字节由 `FFE1 notify` 返回手机。小程序连接 `FFE0` 服务、`FFE1` 特征。BLE 一次通知或写入不是一个完整应用消息，因此必须按字节流解析。

应用帧采用 **ASCII JSON + LF (`0x0A`)**，最大 1024 字节，允许拆包与粘包。小程序按 20 字节分片写入，但主板不能依赖固定分片长度。

## 2. 命令

每条命令含：

```json
{"v":1,"sid":"wx_abcd1234","seq":3,"cmd":"STATUS"}
```

- `v`：协议版本，固定 1。
- `sid`：手机本次连接的随机会话 ID。
- `seq`：会话内严格递增序号。
- `cmd`：`HELLO / STATUS / START / HIT / MISS / STOP`。

带参数示例：

```json
{"v":1,"sid":"wx_abcd1234","seq":2,"cmd":"START","mode":"SMALL","rev":5}
{"v":1,"sid":"wx_abcd1234","seq":3,"cmd":"HIT","target":4,"rev":6}
{"v":1,"sid":"wx_abcd1234","seq":4,"cmd":"MISS","target":2,"rev":7}
```

`mode` 为 `SMALL` 或 `LARGE`。`rev` 和 `target` 必须等于主板当前值，用于拒绝重复点击、迟到命令和压力事件竞态。

## 3. 主板回执

所有命令都必须返回同一 `sid + seq`：

```json
{"v":1,"sid":"wx_abcd1234","seq":3,"ok":true,"state":{"rev":7,"round":1,"mode":"SMALL","phase":"RUNNING","mask":1,"target":4,"flashOn":false,"flashes":0}}
```

拒绝示例：

```json
{"v":1,"sid":"wx_abcd1234","seq":3,"ok":false,"error":"STALE","state":{"rev":8,"round":2,"mode":"SMALL","phase":"RUNNING","mask":0,"target":2,"flashOn":false,"flashes":0}}
```

状态字段：

- `rev`：每次权威状态改变递增。
- `round`：每次 START 或失败重开递增。
- `mode`：`NONE / SMALL / LARGE`。
- `phase`：`IDLE / RUNNING / FLASHING / COMPLETE`。
- `mask`：bit0～bit4 表示 1～5 号已击中。
- `target`：当前目标 1～5；无目标为 0。
- `flashOn`：完成闪烁当前亮灭相位。
- `flashes`：已完成闪烁次数 0～10。
- `progress`：大符流水灯进度 0～5；小符为 0。
- `otherTarget`：大符两靶阶段的另一块靶面；单靶阶段为 0。手机测试约定 `target` 是模拟击中的那块；实物上两块任意一块都可击中。

大符 `RUNNING` 时，`mask` 保持 0，进度看 `progress`；完成闪烁阶段 `mask` 为 31，以兼容现有手机状态校验。

闪烁期间主板可用 `seq=0` 主动推送状态；小程序会接收，但它不对应任何待确认命令。

## 4. 一致性规则

1. 手机不自行推进游戏，只根据主板回执更新。
2. 同一 `seq`、完全相同内容重发时，主板返回缓存回执，不重复执行。
3. 同一 `seq` 内容不同返回 `SEQ_CONFLICT`；旧序号返回 `OLD_SEQ`。
4. 新 `sid` 的 `HELLO` 取得控制权并先停止旧测试。
5. `START/HIT/MISS` 的 `rev` 不匹配返回 `STALE`。
6. `HIT/MISS` 的 `target` 不匹配返回 `STALE`。
7. 连接建立后手机每 1.5 秒发 `STATUS`；主板运行状态 6 秒未收到合法命令必须安全 `STOP`。
8. 手机 4 秒未获 ACK 时显示“执行结果未知”，禁止继续击中，直到重新同步或断开。

建议错误码：`SESSION / OLD_SEQ / SEQ_CONFLICT / STALE / MODE / PHASE / BUSY / BAD_FRAME / INTERNAL`。

## 5. CAN 映射

标准 ID `0x300 + node(1..5)`；`0x300` 为全体广播。除进度命令 DLC=2 外，其余命令 DLC=1。

| 字节0 | 含义 |
|---:|---|
| 0 | OFF：流水灯、靶面关闭 |
| 1 | TARGET_ARROW：箭头 + 靶面 |
| 2 | SMALL_HIT：全红 + 一环 |
| 3 | PROGRESS：字节1为1～5格，靶面全黑 |
| 4 | 小符 FINISH：全红 + 一环 |
| 5 | 大符 FINISH：全红 + 八环 |
| 6 | FINAL_TARGET：流水灯全红，最后靶面保持可击打 |

每次状态改变，主板应重算五个节点的期望命令并发送。正式版本最好让从板返回当前命令/版本；当前从板回执未实现时，手机 ACK 只能证明“主板已接受并排队发送”，不能证明灯板物理点亮。

# 导入、运行与真机调试

## A. 先跑界面（不需要硬件）

1. 安装并登录微信开发者工具。
2. 这部分是保留的小程序方案：选择“导入项目”，目录选 `PnX_Energy_Web`，名称为 `PnX_Energy`。当前网页版无需执行此步骤。
3. 工程暂用 `touristappid`，可先看界面；注册后在 `project.config.json` 换成你自己的 AppID。BLE 真机能力、上传和给别人使用需要正式 AppID。
4. 编译后点“预览”或“真机调试”，用荣耀手机微信扫码。
5. 点“无硬件演示”，分别完成小符、大符、未击中、退出和五击流程。

电脑是否有 BLE 不影响最终方案，因为 BLE 是荣耀手机直接连接 HC-42D；电脑只运行开发者工具。模拟器本身不能代替手机测试 BLE。

## B. 只测 HC-42D

1. 把 HC-42D 插到 HC-T 测试架，USB 连电脑。
2. 安装资料包内 CH340 驱动，设备管理器确认出现 COM 口。
3. 模块未连接手机时，使用厂家串口工具按默认 `9600 8N1` 发送 `AT`（不加 CR/LF），应答 `OK`。
4. 如需改为推荐的 115200，按手册对应的 AT 指令操作；改完模块和 C 板必须保持完全相同。
5. 手机上允许微信使用蓝牙/附近设备；点“连接蓝牙”，选择名称接近 `HC-42` 的设备。

注意：手机连上 BLE 后模块不再进入 AT 配置状态；配置参数要先断开手机。

## C. 用电脑模拟主板

主板固件未完成时，可以让 HC-T 测试架后的电脑代替主板返回协议：

```text
py -m pip install -r tools/requirements.txt
py tools/master_simulator.py --port COM5 --baud 9600
```

把 `COM5` 换成设备管理器中的端口，把波特率换成模块实际值。然后手机连接 HC-42D，模式按钮应解锁。终端会打印每条手机命令和回执。

这条路径验证：小程序 ↔ BLE ↔ HC-42D ↔ UART ↔ 协议。它不验证 C 板和 CAN。

## D. 接真实 C 板

1. 断电后按 `VCC/GND/TXD→RX/RXD←TX` 接线。
2. C 板先只接 HC-42D，不接 CAN，观察 UART 收发和 HELLO ACK。
3. 再接一块从板：给它唯一节点号，CANH/CANL、共地、总线末端 120Ω终端正确。
4. 小程序 START 后应只有目标从板显示箭头+靶面；HIT 后按大小符显示对应稳定灯效。
5. 最后接齐五块板，测试随机不重复、MISS 清零、退出全灭和十次闪烁。

## E. 常见故障

| 现象 | 优先检查 |
|---|---|
| 搜不到 HC-42D | 模块供电、手机蓝牙/附近设备权限、是否被另一台设备占用 |
| 能连接但模式按钮不亮 | 主板没有返回 HELLO ACK；UART TX/RX、共地、波特率或协议换行错误 |
| 立即断开 | FFE0/FFE1不匹配、模块被抢占、距离/供电不稳 |
| 手机显示“状态待确认” | ACK 超时或连接中断；不要继续操作，重连同步 |
| 手机成功但灯不亮 | ACK 只到主板；检查 CAN 发送、节点号、CANH/CANL、终端电阻和从板供电 |
| 字符乱码 | 两端波特率、8N1、TTL/RS232电平错误 |

## F. 发布给别人

纯本地 BLE 控制不需要云服务器，也不需要互联网。要给别人长期使用，需要注册微信小程序 AppID、完成主体/类目和隐私合规配置、上传审核并发布。若未来加入账号、成绩同步、远程排行，才需要云开发或自己的服务器。
